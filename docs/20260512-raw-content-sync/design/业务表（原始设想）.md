## 一、表结构总览

### 1. content_base（内容基础信息表）

```sql
CREATE TABLE `content_base` (
    `id`                        BIGINT UNSIGNED NOT NULL AUTO_INCREMENT COMMENT '自增主键',
    `content_id`                VARCHAR(64) NOT NULL DEFAULT '' COMMENT '内容ID，外部唯一标识',
    `business_content_id`       VARCHAR(64) NOT NULL DEFAULT '' COMMENT '业务内容ID',
    `content_type`              VARCHAR(32) NOT NULL DEFAULT '' COMMENT '内容形式：图文帖、短视频',
    `content_title`             VARCHAR(500) NOT NULL DEFAULT '' COMMENT '内容标题',
    `publish_platform`          VARCHAR(32) NOT NULL DEFAULT '' COMMENT '发布平台：小红书、抖音',
    `publish_time`              DATETIME NOT NULL DEFAULT '1970-01-01 00:00:00' COMMENT '发布时间',
    `publish_url`               VARCHAR(1024) NOT NULL DEFAULT '' COMMENT '发布链接',
    `business_line`             VARCHAR(64) NOT NULL DEFAULT '' COMMENT '业务线：hotel、public',
    `content_source`            VARCHAR(64) NOT NULL DEFAULT '' COMMENT '内容来源/大业务方向划分',
    `production_team`           VARCHAR(128) NOT NULL DEFAULT '' COMMENT '生产归属团队/投放团队/代理名称',
    `operation_project`         VARCHAR(128) NOT NULL DEFAULT '' COMMENT '运营项目',
    `placement_position`        VARCHAR(128) NOT NULL DEFAULT '' COMMENT '投放版位',
    `dt`                        DATE NOT NULL DEFAULT '1970-01-01' COMMENT '数据更新日期，标识最新版本',
    `create_time`               DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
    `update_time`               DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',

    UNIQUE KEY `uniq_content_id` (`content_id`),
    KEY `idx_business_content_id` (`business_content_id`),
    KEY `idx_publish_platform` (`publish_platform`),
    KEY `idx_publish_time` (`publish_time`),
    KEY `idx_business_line` (`business_line`),
    KEY `idx_content_type` (`content_type`),
    KEY `idx_biz_ctime` (`business_line`, `publish_time`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='内容基础信息表';
```

## 二、表关系与关联方式

```
content_base (id)
    ├── content_text    (base_id → content_base.id)
    ├── content_image   (base_id → content_base.id)
    ├── content_video   (base_id → content_base.id)
    ├── content_metrics (base_id → content_base.id, UNIQUE)
    └── content_label   (base_id → content_base.id, UNIQUE)
```

| 子表 | 与 base 关系 | base_id 约束 |
|------|-------------|-------------|
| content_text | 一对一（当前） | 普通索引 |
| content_image | 一对多 | 普通索引 |
| content_video | 一对一（当前，预留多行） | 普通索引 |
| content_metrics | 一对一 | UNIQUE |
| content_label | 一对一 | UNIQUE |

## 三、关键设计决策记录

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 主键策略 | base 表用 `id BIGINT` 自增，`content_id` UNIQUE KEY |
| 2 | dt 字段位置 | 放 content_base，标识基础信息最新版本；metrics 只存最新值 |
| 3 | content_type 位置 | 放 content_base 统一标记，不发散到各子表 |
| 4 | content_url 处理 | 按内容类型分别存 image 表（图片URL）和 video 表（视频URL） |
| 5 | ext_param 类型 | 统一用 `VARCHAR(3000) NOT NULL DEFAULT '{}'`，不用 JSON 类型 |
| 6 | 冗余策略 | text/image/video 表冗余 `content_title` + `poi`；metrics 不做冗余 |
| 7 | image 去重 | `original_url` UNIQUE KEY(255)，重复时 ON DUPLICATE KEY UPDATE reference_count+1 |
| 8 | video 去重 | `video_url` UNIQUE KEY(255)，与 image 保持一致 |
| 9 | video 预处理状态 | `preprocess_status` TINYINT：0-未处理，1-已抽帧，2-已提取音频，3-已转文字，4-全部完成 |
| 10 | video 抽帧参数 | `video_frame_param` 格式 `{"frame":[{...}]}`，frameList 包含抽帧图片链接 |
| 11 | AI 标签结构 | `ai_tag` JSON 类型，简单字符串列表如 `["攻略型","酒店"]`，用于 ES 检索 |
| 12 | AI 全量结果 | `ai_tag_detail` MEDIUMTEXT 存完整 JSON |
| 13 | AI 任务关联 | `task_id` 唯一，一个 content 只有一个任务，覆盖更新 |
| 14 | city/poi 归属 | 原计划放 label 表，最终在 content_label 中落定 |
| 15 | sync_status | 仅保留在原始宽表，不进业务表 |
| 16 | 子表索引规范 | content 粒度表 base_id 普通索引；一对一表 base_id UNIQUE |
| 17 | 审计字段 | 所有表均包含 `create_time` + `update_time` |
| 18 | 字符集 | 全部 utf8mb4 + utf8mb4_unicode_ci |
| 19 | 引擎 | 全部 InnoDB |
