# MediaInfo 执行器 — 技术方案

## 需求

新增一个任务执行器，数据源为**音频链接 + 图片链接 + prompt**，不依赖 OSS 服务，仅执行：
1. ASR 语音转写
2. 大模型图片理解

## 架构

```
用户数据（items[]）
    │ businessId, audioUrl, imageUrls[], prompt
    ▼
MediaInfoExecutor.execute()
    │ 解析数据源 → 创建 N 个子任务
    ▼
QSchedule 调度子任务
    ▼
MediaInfoExecutor.subExecute()
    │ 查找匹配的 MediaProcessor
    ▼
MediaInfoProcessor.process()
    │ 1. ASR 转写（直接用 audioUrl，不经 OSS）
    │ 2. LLM 图片理解（直接用 imageUrls，不经 OSS）
    │ 3. 合并结果
    ▼
子任务完成
```

## 与 TaggingExecutor 的区别

| 维度 | TaggingExecutor | MediaInfoExecutor |
|------|----------------|-------------------|
| 数据源 | 视频链接 | 音频链接 + 图片链接 + prompt |
| OSS 依赖 | 是（抽帧/音频提取后上传 OSS） | 否（直接使用原始 URL） |
| 视频处理 | 下载→抽帧→音频提取 | 不涉及 |
| ASR | 通过 OSS URL | 直接使用原始音频 URL |
| 图片理解 | 通过 OSS URL | 直接使用原始图片 URL |
| 流程步骤 | 6 步（含下载/抽帧/音频提取） | 2 步（ASR → 图片理解） |

## 数据源定义

### 用户输入 data

```json
{
  "items": [
    {
      "businessId": "material_001",
      "audioUrl": "https://example.com/audio.mp3",
      "imageUrls": ["https://example.com/img1.jpg", "https://example.com/img2.jpg"],
      "prompt": "请分析这条广告素材的卖点和情感倾向"
    }
  ]
}
```

### 子任务 subTaskParams

```json
{
  "audioUrl": "https://example.com/audio.mp3",
  "imageUrls": ["https://example.com/img1.jpg", "https://example.com/img2.jpg"],
  "prompt": "请分析这条广告素材的卖点和情感倾向",

}
```

## 关键设计决策

1. **不依赖 OSS**：ASR 和图片理解 API 均支持直接传入 URL，无需中转 OSS
2. **音频格式探测**：根据 URL 后缀自动识别音频格式（mp3/wav/aac 等），默认 mp3
3. **ASR provider 可配**：通过 executor params 配置 BYTEDANCE / ALIYUN
4. **断点续传**：保留 TaggingProgress 类似的 Step 进度机制，支持 ASR → 图片理解两步断点
5. **复用 MediaProcessor 链**：subExecute 沿用现有 MediaProcessor 分发模式，MediaInfoProcessor 通过 `supports()` 匹配含有 audioUrl + imageUrls 的子任务
