统一内容检索入口，支持 MySQL / ES 双引擎路由

路由决策原则

一旦任一条件触发 ES（label/metrics/时间范围），全部条件走 ES，不拆分部分走 MySQL。

▶ MySQL 路由：仅 contentTypes / platforms / businessLine / contentSource / keyword
▶ ES 路由：cities / poi / aiTags / sortField(指标) / publishTime 范围

ResponseAssembler 响应结构

最终响应包含三部分：
hits — 全量字段的 Document 列表
total — 命中总数
fieldMeta — 字段元信息，标记 default: true/false，前端据此决定默认展示列

异步埋点设计

CompletableFuture.runAsync() + 独立线程池
5 种事件：search / browse / download / sort / column_customize
关键：异常仅记日志，零容忍阻塞主流程

安全过滤策略

扫描 publish_url 字段，按 QConfig 配置的前缀映射替换。
无匹配则原值返回，配置为空则跳过。
QConfig 变更实时生效，无需重启。

MySQL 查询约束

只查 content_base 单表，不 JOIN 其他表。
keyword 使用 LIKE 模糊匹配（仅 content_title 短字段）。
‍数据量大时自然走 ES 路由，不会卡在 MySQL。

ES 查询优化

fetchSource(false) 仅取 _id，减少网络开销。
sortField 白名单校验防止恶意注入。
分页受 ES max_result_window(10000) 限制。
