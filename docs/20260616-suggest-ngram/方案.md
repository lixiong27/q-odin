# ES Suggest Ngram 改造 & 无感迁移方案

> 2026-06-16
> 作者: AI

## 背景

`MaterialSuggestService#suggest` 使用 `wildcardQuery(field, "*" + keyword + "*")` 做前置过滤。在 keyword 类型字段上，leading wildcard 会遍历整个 term dictionary，超过 `max_wildcard_expansion` 阈值时 ES 静默返回 0 条。

**现场验证：**
- `field=material_label_common_tag&q=北京` → 有结果（如 `北京天安门广场氛围感空镜`）
- `field=material_label_common_tag&q=空镜` → 无结果
- 但索引中存在 `承德避暑山庄氛围感空镜` 等含"空镜"的标签

原因：`*北京*` 匹配到的 term 数较少（标签中带"北京"的相对集中），未超阈值；`*空镜*` 作为常见后缀匹配到的 term 数超阈值，ES 静默拦截。

## 方案：Ngram + Side Index 零停机迁移

### 思路

1. 给 `material_label_common_tag` keyword 字段加一个 ngram 子字段（type=text, analyzer=ngram）
2. 查询时：`match` 查 `.ngram` 子字段做模糊匹配，`terms` 聚合仍查主 keyword 字段（返回完整标签值）
3. 新建一个侧索引（如 `odin_material_search_v2`），建好 ngram mapping 后全量同步
4. 通过 QConfig 热配索引名实现零停机切换

### 工作原理

`min_gram=2, max_gram=2`（bigram）分词示例：

```
输入: "北京天安门广场氛围感空镜"
bigrams: 北京, 京天, 天安, 安门, 门广, 广场, 场氛, 氛围, 围感, 感空, 空镜
```

搜索 `空镜` → `match` 查询 → 分词为 `空镜` → 命中倒排索引中所有含 `空镜` bigram 的文档。

相比 wildcard 的优势：
- 基于倒排索引，不是 term 词典遍历
- 无 `max_wildcard_expansion` 限制
- 支持任意位置的子串匹配（前缀、中缀、后缀均可）

## 改动清单

### 1. MaterialBaseMapper.java + MaterialBaseMapper.xml

**路径**: `infra/dao/MaterialBaseMapper.java` + `resources/mapper/MaterialBaseMapper.xml`

新增两个方法：
- `int count()` — `SELECT COUNT(1) FROM material_base`
- `List<String> selectMaterialIdByPage(@Param("offset") int offset, @Param("limit") int limit)` — `SELECT material_id FROM material_base ORDER BY id LIMIT #{limit} OFFSET #{offset}`

目的：reindex 时从 MySQL 分页扫描所有 material_id。

### 2. ElasticsearchDataSource.java

**路径**: `infra/elasticsearch/ElasticsearchDataSource.java`

新增方法：
- `boolean deleteIndex(String index)` — 使用 `DeleteIndexRequest` 删除索引

目的：reindex 时需要先清理已有侧索引（幂等重建）。

### 3. EsIndexConfig.java

**路径**: `infra/config/EsIndexConfig.java`

`getMaterialSearchIndexName()` 改为支持热配覆盖：
```java
public String getMaterialSearchIndexName() {
    String override = hotFileQConfig.getString("es.index.material.name", null);
    if (StringUtils.isNotBlank(override)) {
        return override;
    }
    return getIndexName(MATERIAL_SEARCH_INDEX);
}
```

需要注入 `HotFileQConfig`。

目的：切换零停机 —— QConfig 改一个 key 即可切换索引，不需要重启。

### 4. MaterialSearchSyncService + MaterialSearchSyncServiceImpl

**接口路径**: `service/es/MaterialSearchSyncService.java`
**实现路径**: `service/es/impl/MaterialSearchSyncServiceImpl.java`

接口新增：
```java
boolean syncToIndex(String materialId, String indexName);
```

实现：
- `sync()` 改为委托 `syncToIndex(materialId, esIndexConfig.getMaterialSearchIndexName())`
- `syncToIndex` 接受显式 indexName，跳过 ensureIndexExists，直接 assemble + upsert

目的：reindex 时写入到新索引，不依赖 `esIndexConfig` 的当前配置。

### 5. MaterialSuggestService.java

**路径**: `service/es/MaterialSuggestService.java`

核心改动：`wildcardQuery` → `matchQuery` + 单字符降级

```java
if (StringUtils.isNotBlank(keyword)) {
    if (keyword.length() == 1) {
        // 单字符: ngram min_gram=2 无法生成 token，降级为 wildcard
        boolQuery.filter(QueryBuilders.wildcardQuery(field, "*" + keyword + "*"));
    } else {
        // 多字符: 用 ngram 子字段做 match 搜索
        boolQuery.filter(QueryBuilders.matchQuery(field + ".ngram", keyword));
    }
}
```

注意：`terms` 聚合保持在原始 keyword 字段（`field`），确保返回完整标签值而不是 ngram token。

### 6. MaterialSearchReindexTask.java — 新增 QSchedule 全量重建任务

**路径**: `task/es/MaterialSearchReindexTask.java`

参照 `ContentFullRebuildTask` 风格，新增一个 QSchedule 定时任务：

```java
package com.qunar.ug.flight.contact.odin.server.task.es;

import com.qunar.flight.qmonitor.QMonitor;
import com.qunar.ug.flight.contact.odin.server.infra.dao.MaterialBaseMapper;
import com.qunar.ug.flight.contact.odin.server.infra.elasticsearch.ElasticsearchDataSource;
import com.qunar.ug.flight.contact.odin.server.infra.qconfig.IndexQConfig;
import com.qunar.ug.flight.contact.odin.server.service.es.MaterialSearchSyncService;
import org.apache.commons.collections4.CollectionUtils;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Service;
import qunar.tc.qschedule.config.QSchedule;
import qunar.tc.schedule.Parameter;
import qunar.tc.schedule.TaskHolder;
import qunar.tc.schedule.TaskMonitor;

import javax.annotation.Resource;
import java.util.List;

/**
 * 素材 ES 索引全量重建任务（ngram 迁移）
 * <p>
 * 受 material.es.reindex.enabled 开关控制，由 QSchedule 触发。
 * 流程：创建新索引（含 ngram mapping）→ 从 MySQL 全量同步 → 待验证后手动切换
 * <p>
 * 注意：本任务只负责「创建+同步」，不负责「切换」。
 * 切换由 hotfile.properties 中 es.index.material.name 控制。
 */
@Service
public class MaterialSearchReindexTask {

    private static final Logger LOG = LoggerFactory.getLogger(MaterialSearchReindexTask.class);

    @Resource
    private MaterialBaseMapper materialBaseMapper;

    @Resource
    private MaterialSearchSyncService materialSearchSyncService;

    @Resource
    private ElasticsearchDataSource elasticsearchDataSource;

    @Resource
    private IndexQConfig indexQConfig;

    @QSchedule("mkt_odin_material_es_reindex")
    public void reindexTask(Parameter param) {
        LOG.info("素材 ES 全量重建任务开始");
        final TaskMonitor monitor = TaskHolder.getKeeper();
        monitor.autoAck(false);

        try {
            if (!indexQConfig.isRepairEnabled()) {
                monitor.getLogger().info("ES full rebuild disabled by config");
                return;
            }
            doReindex(monitor);
        } catch (Exception e) {
            LOG.error("素材 ES 全量重建异常", e);
        } finally {
            if (!monitor.isStopped()) {
                monitor.finish();
            }
        }
    }

    /**
     * 主流程：创建侧索引 → 全量同步 → 等待人工切换
     */
    private void doReindex(TaskMonitor monitor) {
        // 1. 准备新索引名：odin_material_search_v2
        String V2_SUFFIX = "_v2";
        String newIndexName = getNewIndexName(V2_SUFFIX);

        // 2. 若已存在则删除重建（幂等）
        String settings = indexQConfig.getMaterialIndexSettings();
        String mappings = indexQConfig.getMaterialIndexMappings();
        createIndexIfNeeded(newIndexName, settings, mappings);

        // 3. 从 MySQL 分页读取全量素材，写入新索引
        long total = materialBaseMapper.count();
        if (total <= 0) {
            monitor.getLogger().info("No data to reindex, count=0");
            return;
        }

        int batchSize = indexQConfig.getRepairBatchSize();
        int success = 0;
        int fail = 0;

        LOG.info("素材 ES 全量重建: total={}, batchSize={}, targetIndex={}", total, batchSize, newIndexName);
        monitor.setRateCapacity((int) total);

        for (int offset = 0; offset < total; offset += batchSize) {
            List<String> materialIds = materialBaseMapper.selectMaterialIdByPage(offset, batchSize);
            if (CollectionUtils.isEmpty(materialIds)) {
                continue;
            }

            for (String materialId : materialIds) {
                try {
                    boolean ok = materialSearchSyncService.syncToIndex(materialId, newIndexName);
                    if (ok) {
                        success++;
                    } else {
                        fail++;
                    }
                } catch (Exception e) {
                    LOG.error("同步失败: materialId={}", materialId, e);
                    fail++;
                }
            }

            monitor.addRate(materialIds.size());
            if ((offset + batchSize) % (batchSize * 10) == 0) {
                LOG.info("素材 ES 全量重建进度: {}/{}", Math.min(offset + batchSize, total), total);
            }
        }

        QMonitor.recordMany("material_es_reindex_total", success, 0);
        if (fail > 0) {
            QMonitor.recordMany("material_es_reindex_fail", fail, 0);
        }

        monitor.getLogger().info("素材 ES 全量重建完成: total={}, success={}, fail={}, newIndex={}",
                total, success, fail, newIndexName);
        LOG.info("素材 ES 全量重建完成: total={}, success={}, fail={}, newIndex={}",
                total, success, fail, newIndexName);
    }

    /**
     * 获取侧索引名
     */
    private String getNewIndexName(String suffix) {
        // EsIndexConfig 不方便提供，直接拼接
        // hotfile 中可以用 es.index.material.suffix 自定义后缀
        // 默认 _v2
        return "odin_material_search" + suffix;
    }

    /**
     * 创建新索引，已存在则删除重建
     */
    private void createIndexIfNeeded(String indexName, String settings, String mappings) {
        try {
            if (elasticsearchDataSource.existIndex(indexName)) {
                LOG.warn("新索引已存在，将删除重建: index={}", indexName);
                elasticsearchDataSource.deleteIndex(indexName);
            }
        } catch (Exception e) {
            LOG.warn("检查索引状态异常，将尝试直接创建: index={}", indexName, e);
        }

        boolean created = elasticsearchDataSource.create(indexName, settings, mappings);
        if (created) {
            LOG.info("新索引创建成功: index={}", indexName);
        } else {
            LOG.warn("新索引创建失败（可能已存在）: index={}", indexName);
        }
    }
}
```

## 主流程逻辑（核心流程）

```
部署代码（改动 1-6）
    │
    ▼
更新 hotfile.properties 中的 mapping 和 settings（改动 7）
    │ 注：此时只改了热配，现有索引不受影响
    ▼
在 QSchedule 平台触发 mkt_odin_material_es_reindex
    │
    ├── 第1步：拼接新索引名 odin_material_search_v2
    ├── 第2步：若 v2 索引已存在则删除（幂等）
    ├── 第3步：从 hotfile 读取最新 settings + mappings
    ├── 第4步：创建新索引（含 ngram analyzer + mapping）
    ├── 第5步：SELECT COUNT(1) FROM material_base 获取总数
    ├── 第6步：分页 SELECT material_id → syncToIndex() → 写入 v2 索引
    │       循环直至全部完成
    └── 第7步：输出统计 total/success/fail
    │
    ▼ 人工验证阶段
验证 v2 索引 mapping 和数据量
    │
    ▼
在 hotfile.properties 中新增配置（零停机切换）
es.index.material.name=odin_material_search_v2
    │
    ▼
suggest + sync 自动指向 v2 索引，旧索引保留作回滚
```

**关键原则**：
- QSchedule 只负责「创建 + 同步」，不负责「切换」
- 切换由 QConfig 热配控制，部署零耦合
- 回滚只需删除/修改 hotfile 中的 `es.index.material.name`，即刻切回旧索引

## 无感切换步骤

| 步骤 | 操作 | 影响 |
|------|------|------|
| 1 | 部署所有代码改动 | suggest 仍用 wildcard 查旧索引，无影响 |
| 2 | 更新 hotfile mapping+settings | 仅对新索引生效，无影响 |
| 3 | 触发 QSchedule 任务 `mkt_odin_material_es_reindex` | 全量同步期间无查询影响（新索引尚未切换） |
| 4 | 验证 v2 索引 mapping + 文档数 | — |
| 5 | 新增 `es.index.material.name=odin_material_search_v2` | 瞬间切换，出现问题时即刻回滚 |
| 6（可选） | 稳定后清理旧索引 | 手动通过 curl/kibana 删除 |

## 验证方法

1. **reindex 后对比文档数**：ES v2 索引 count ≈ MySQL `SELECT COUNT(1) FROM material_base`
2. **验证 mapping**：`GET odin_material_search_v2/_mapping` 确认 `material_label_common_tag` 含 `fields.ngram`
3. **suggest 空镜**：`GET /api/material/suggest?field=material_label_common_tag&q=空镜` → 应返回含"空镜"的标签
4. **suggest 北京（回归）**：`GET /api/material/suggest?field=material_label_common_tag&q=北京` → 应与之前一致
5. **热门 suggest**：`GET /api/material/suggest?field=material_label_common_tag`（无 q）→ 应返回 Top N
6. **增量同步**：新建一条素材 → 确认出现在 v2 索引
