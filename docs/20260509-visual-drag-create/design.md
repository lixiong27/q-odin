# 可视化拖拽创建功能设计

## 一、需求概述

**现状**：新建分类/标签需点击按钮 → 弹窗表单 → 填写信息 → 提交落库

**目标**：支持从工具栏拖拽图标到画布 → 直接生成节点 → 填写信息 → 批量保存落库

**核心原则**：拖拽操作仅在前端内存中创建节点，点击"保存"按钮才调用后端接口落库

**状态**：✅ 已实现

---

## 二、交互流程设计

### 2.1 当前流程 vs 目标流程

```
【当前】
点击"新建分类" → 弹窗表单 → 填写 → 提交 → 后端创建 → 刷新列表

【目标】
拖拽图标到画布 → 生成临时节点 → 编辑信息 → 点击"保存" → 批量落库
```

### 2.2 详细交互

```
1. 工具栏区域
   ┌─────────────────────────────────────────┐
   │  [📁 分类] [🏷️ 标签]                    │  ← 可拖拽的创建按钮
   └─────────────────────────────────────────┘

2. 拖拽到画布
   - 拖拽时：显示半透明预览节点 + 目标位置指示
   - 释放时：在目标位置创建临时节点（虚线边框标识未保存）

3. 临时节点状态
   - 虚线边框 + "未保存" 标签
   - 右侧面板自动打开，填写信息
   - 支持继续拖拽调整位置

4. 批量保存
   - 工具栏显示"保存"按钮 + 未保存节点数量
   - 点击保存 → 校验 → 批量调用后端 → 落库成功后节点变为实线
```

## 三、技术方案

### 3.1 数据结构

```javascript
// 现有节点（已落库）
const existingNode = {
  id: 'category_123',      // 服务端 ID
  dbId: 123,
  type: 'category',
  status: 'saved',         // 新增：保存状态
  ...
}

// 新增：临时节点（未落库）
const tempNode = {
  id: 'temp_category_xxx', // 临时 ID（前端生成）
  dbId: null,              // 未落库，无服务端 ID
  type: 'category',
  status: 'unsaved',       // 新增：保存状态
  tempId: 'uuid-xxx',      // 前端生成的唯一标识
  ...
}
```

### 3.2 状态管理

```javascript
// 新增状态
const [unsavedNodes, setUnsavedNodes] = useState([]);  // 未保存节点
const [hasUnsavedChanges, setHasUnsavedChanges] = useState(false);  // 是否有未保存变更

// 合并显示
const allNodes = [...savedNodes, ...unsavedNodes];
```

### 3.3 保存流程

```javascript
const handleSave = async () => {
  // 1. 校验所有未保存节点
  const invalidNodes = unsavedNodes.filter(n => !validateNode(n));
  if (invalidNodes.length > 0) {
    message.error('请完善节点信息');
    return;
  }

  // 2. 按依赖顺序排序（父分类先于子分类创建）
  const sortedNodes = topologicalSort(unsavedNodes);

  // 3. 逐个调用后端创建
  for (const node of sortedNodes) {
    const result = await createCategory(node);
    // 更新节点 ID 映射（临时 ID → 服务端 ID）
    updateNodeIdMapping(node.tempId, result.id);
  }

  // 4. 刷新数据
  loadData();
  setUnsavedNodes([]);
  setHasUnsavedChanges(false);
};
```

## 四、待讨论细节

### 4.1 拖拽放置规则

**问题**：拖拽到什么位置可以创建节点？

**方案选项**：
- A：只能拖拽到空白区域，创建根节点
- B：可以拖拽到现有节点上，自动建立父子关系
- C：两者都支持，通过拖拽位置区分

**讨论点**：
- 分类拖到分类上 → 成为子分类？
- 标签拖到末级分类上 → 自动关联？
- 标签拖到非末级分类上 → 提示不允许？

### 4.2 未保存节点的父子关系

**问题**：拖拽创建的临时节点，父子关系如何处理？

**场景**：
```
1. 先拖拽创建父分类（未保存）
2. 再拖拽创建子分类（未保存），放在父分类下
3. 保存时，如何保证父分类先创建？
```

**方案**：
- 前端维护临时父子关系
- 保存时按拓扑排序依次创建
- 或者：要求先保存父节点，再创建子节点

### 4.3 取消/撤销机制

**问题**：如何取消未保存的节点？

**方案选项**：
- A：单个节点删除按钮
- B：全局"放弃所有未保存"按钮
- C：两者都支持

### 4.4 编辑未保存节点

**问题**：未保存节点如何编辑？

**方案**：
- 点击选中 → 右侧面板编辑
- 支持继续拖拽调整位置
- 支持修改父子关系（再拖拽一次）

### 4.5 页面刷新/离开提醒

**问题**：有未保存节点时，刷新页面怎么办？

**方案**：
```javascript
useEffect(() => {
  const handleBeforeUnload = (e) => {
    if (hasUnsavedChanges) {
      e.preventDefault();
      e.returnValue = '';
    }
  };
  window.addEventListener('beforeunload', handleBeforeUnload);
  return () => window.removeEventListener('beforeunload', handleBeforeUnload);
}, [hasUnsavedChanges]);
```

### 4.6 与现有拖拽功能的关系

**问题**：现有的"移动节点"拖拽功能如何共存？

**现有功能**：拖拽已存在节点 → 移动位置/修改父子关系 → 立即落库

**新功能**：拖拽创建图标 → 创建临时节点 → 批量保存

**方案**：
- 工具栏图标 → 创建模式（临时节点）
- 画布节点 → 移动模式（立即落库）
- 通过拖拽源区分

## 五、UI 设计要点

### 5.1 视觉区分

| 状态 | 边框 | 标识 | 操作 |
|------|------|------|------|
| 已保存 | 实线 | 无 | 可移动、可编辑 |
| 未保存 | 虚线 + 橙色 | "未保存"标签 | 可删除、可编辑、可移动 |
| 保存中 | 虚线 + 蓝色 | loading 动画 | 禁用操作 |

### 5.2 工具栏设计

```
┌─────────────────────────────────────────────────────────────┐
│ [📁 拖拽创建分类] [🏷️ 拖拽创建标签] │ [💾 保存(3)] │
│                                     ↑ 未保存节点数量         │
└─────────────────────────────────────────────────────────────┘
```
