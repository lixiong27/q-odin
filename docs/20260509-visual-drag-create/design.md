# 可视化拖拽创建功能设计

## 一、需求概述

**现状**：新建分类/标签需点击按钮 → 弹窗表单 → 填写信息 → 提交落库

**目标**：支持从工具栏拖拽图标到画布 → 直接生成节点 → 填写信息 → 批量保存落库

**核心原则**：拖拽操作仅在前端内存中创建节点，点击"保存"按钮才调用后端接口落库

**状态**：✅ 已实现

---

## 二、交互流程设计

### 2.1 当前流程 vs 目标流程

```
【当前】
点击"新建分类" → 弹窗表单 → 填写 → 提交 → 后端创建 → 刷新列表

【目标】
拖拽图标到画布 → 生成临时节点 → 编辑信息 → 点击"保存" → 批量落库
```

### 2.2 详细交互

```
1. 工具栏区域
   ┌─────────────────────────────────────────┐
   │  [📁 分类] [🏷️ 标签]                    │  ← 可拖拽的创建按钮
   └─────────────────────────────────────────┘

2. 拖拽到画布
   - 拖拽时：显示半透明预览节点 + 目标位置指示
   - 释放时：在目标位置创建临时节点（虚线边框标识未保存）

3. 临时节点状态
   - 虚线边框 + "未保存" 标签
   - 右侧面板自动打开，填写信息
   - 支持继续拖拽调整位置

4. 批量保存
   - 工具栏显示"保存"按钮 + 未保存节点数量
   - 点击保存 → 校验 → 批量调用后端 → 落库成功后节点变为实线
```

## 三、技术方案

### 3.1 数据结构

```javascript
// 现有节点（已落库）
const existingNode = {
  id: 'category_123',      // 服务端 ID
  dbId: 123,
  type: 'category',
  status: 'saved',         // 新增：保存状态
  ...
}

// 新增：临时节点（未落库）
const tempNode = {
  id: 'temp_category_xxx', // 临时 ID（前端生成）
  dbId: null,              // 未落库，无服务端 ID
  type: 'category',
  status: 'unsaved',       // 新增：保存状态
  tempId: 'uuid-xxx',      // 前端生成的唯一标识
  ...
}
```

### 3.2 状态管理

```javascript
// 新增状态
const [unsavedNodes, setUnsavedNodes] = useState([]);  // 未保存节点
const [hasUnsavedChanges, setHasUnsavedChanges] = useState(false);  // 是否有未保存变更

// 合并显示
const allNodes = [...savedNodes, ...unsavedNodes];
```

### 3.3 保存流程

```javascript
const handleSave = async () => {
  // 1. 校验所有未保存节点
  const invalidNodes = unsavedNodes.filter(n => !validateNode(n));
  if (invalidNodes.length > 0) {
    message.error('请完善节点信息');
    return;
  }

  // 2. 按依赖顺序排序（父分类先于子分类创建）
  const sortedNodes = topologicalSort(unsavedNodes);

  // 3. 逐个调用后端创建
  for (const node of sortedNodes) {
    const result = await createCategory(node);
    // 更新节点 ID 映射（临时 ID → 服务端 ID）
    updateNodeIdMapping(node.tempId, result.id);
  }

  // 4. 刷新数据
  loadData();
  setUnsavedNodes([]);
  setHasUnsavedChanges(false);
};
```

## 四、需求确认记录

### 2026-05-09 讨论确认

#### 4.1 拖拽放置规则 ✅ 已确认

**决定**：方案 B + 空白区域放置

| 拖拽源 | 放置目标 | 结果 |
|--------|----------|------|
| 分类按钮 | 空白区域 | 创建根分类（孤儿分类） |
| 分类按钮 | 已保存非末级分类 | 创建子分类 |
| 分类按钮 | 未保存非末级分类 | 创建子分类（临时父子关系） |
| 分类按钮 | 末级分类 | ❌ 提示"末级分类不能有子分类" |
| 分类按钮 | 标签 | ❌ 提示"分类不能创建在标签下" |
| 标签按钮 | 空白区域 | 创建孤儿标签 |
| 标签按钮 | 末级分类 | 创建关联标签 |
| 标签按钮 | 非末级分类 | ❌ 提示"标签只能关联末级分类" |

#### 4.2 未保存节点父子关系 ✅ 已确认

**决定**：支持临时父子关系，按拓扑排序保存

**场景示例**：
```
1. 拖拽创建分类A（未保存，非末级）
2. 拖拽创建分类B，放到分类A下（临时父子关系）
3. 拖拽创建标签C，放到分类B下（需先将B设为末级）
4. 保存时：A → B → C 依次创建
```

#### 4.3 取消/撤销机制 ✅ 已确认

**决定**：方案 A - 单个节点删除按钮（右侧面板）

#### 4.4 编辑未保存节点 ✅ 已确认

- 点击选中 → 右侧面板编辑
- 支持继续拖拽调整位置和父子关系

#### 4.5 页面离开提醒 ✅ 已确认

- 有未保存节点时刷新页面提示确认

#### 4.6 默认名称 ✅ 已确认

- 分类默认名称："新分类1"、"新分类2"...
- 标签默认名称："新标签1"、"新标签2"...

#### 4.7 Code重复校验 ✅ 已确认

**决定**：前端预校验

**校验范围**：
- 与已保存节点的 code 重复
- 与其他未保存节点的 code 重复

**校验时机**：点击"保存"按钮时

#### 4.8 批量保存接口 ✅ 已确认

**决定**：保持逐个调用创建接口

**原因**：
- 后端无需新接口
- 前端拓扑排序保证顺序

## 五、UI 设计要点

### 5.1 视觉区分

| 状态 | 边框 | 标识 | 操作 |
|------|------|------|------|
| 已保存 | 实线 | 无 | 可移动、可编辑 |
| 未保存 | 虚线 + 橙色 | "未保存"标签 | 可删除、可编辑、可移动 |
| 保存中 | 虚线 + 蓝色 | loading 动画 | 禁用操作 |

### 5.2 工具栏设计

```
┌─────────────────────────────────────────────────────────────┐
│ [📁 拖拽创建分类] [🏷️ 拖拽创建标签] │ [💾 保存(3)] │
│                                     ↑ 未保存节点数量         │
└─────────────────────────────────────────────────────────────┘
```
