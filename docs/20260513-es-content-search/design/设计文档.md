# 数仓宽表 ES 加速查询方案

## 一、需求概述

### 1.1 背景

当前数仓宽表（`content_base` + 子表）数据存储在 MySQL 中，支持存量和增量同步。随着数据量增长，MySQL 的复杂查询（如按标题/POI/标签模糊检索、多维度筛选）性能下降明显。

**业务指标：**
- 宽表每日更新（部分数据更新，非全量覆盖）
- AI 标签（aiTag）通过定时任务异步更新，具有随机性
- 根据 `content_id` 确认是否已同步到 `content_base`，实现去重

### 1.2 目标

- 使用 Elasticsearch 加速宽表数据的查询能力
- 支持存量初始化 + 增量实时同步
- 只能使用原生 ES Client（`RestHighLevelClient`），不引入 ORM 封装
- 与现有 `content_base` 表保持数据一致性

### 1.3 约束

- 不使用 Spring Data ES 等高级封装，只用原生 `RestHighLevelClient`
- ES 索引需按日期分片，便于管理和滚动清理
- 与现有 `RawContentSyncService` 同步流程解耦，通过监听/回调触发 ES 更新

### 2.3 ES DataSource 封装

复用现有的 `ElasticsearchDataSource`，新增方法以支持更新操作。

#### 2.3.1 索引管理服务

```java
@Component
public class ContentIndexService {

    private static final String INDEX_PREFIX = "content_base";
    
    @Resource
    private ElasticsearchDataSource elasticsearchDataSource;
    
    @Resource
    private HotFileQConfig hotFileQConfig;

    private static final DateTimeFormatter DATE_FORMATTER = 
        DateTimeFormatter.ofPattern("yyyyMMdd");

    /**
     * 获取当日索引名
     */
    private String getIndexName() {
        return INDEX_PREFIX + "_" + LocalDate.now().format(DATE_FORMATTER);
    }

    /**
     * 确保索引存在，不存在则创建
     */
    public void ensureIndexExists() {
        String index = getIndexName();
        if (!elasticsearchDataSource.existIndex(index)) {
            String settings = buildSettings();
            String mappings = buildMappings();
            elasticsearchDataSource.create(index, settings, mappings);
        }
    }

    /**
     * 批量写入/更新文档
     * 使用 contentId 作为 ES 文档 ID，天然去重
     */
    public boolean upsertDocuments(List<ContentBaseEsDoc> docs) {
        if (CollectionUtils.isEmpty(docs)) {
            return true;
        }
        String index = getIndexName();
        ensureIndexExists();

        // 使用原生 BulkRequest，每条数据设置 contentId 为文档 ID
        BulkRequest bulkRequest = new BulkRequest();
        docs.forEach(doc -> {
            IndexRequest request = new IndexRequest(index)
                .id(doc.getContentId())             // 以 contentId 为文档 ID
                .source(JsonUtils.toJson(doc), XContentType.JSON);
            bulkRequest.add(request);
        });

        try {
            BulkResponse response = 
                elasticsearchDataSource.getRestHighLevelClient()
                    .bulk(bulkRequest, RequestOptions.DEFAULT);
            if (response.hasFailures()) {
                log.error("ES bulk upsert failed: {}", response.buildFailureMessage());
                return false;
            }
            return true;
        } catch (Exception e) {
            log.error("ES bulk upsert error", e);
            return false;
        }
    }

    /**
     * 构建 Settings
     */
    private String buildSettings() {
        int shards = hotFileQConfig.getInt("es.index.shards", 3);
        int replicas = hotFileQConfig.getInt("es.index.replicas", 1);
        return String.format("{\"number_of_shards\": %d, \"number_of_replicas\": %d}", 
            shards, replicas);
    }

    /**
     * 构建 Mappings
     */
    private String buildMappings() {
        return "{...}"; // 详见上方 Mapping 定义
    }
}
```

#### 2.3.2 数据同步入口

```java
@Service
@Slf4j
public class ContentIndexSyncService {

    @Resource
    private ContentBaseMapper contentBaseMapper;

    @Resource
    private ContentIndexService contentIndexService;

    /**
     * 全量初始化：将 content_base 全部数据导入 ES
     */
    @Transactional(readOnly = true)
    public void fullSync(int batchSize) {
        long total = contentBaseMapper.countAll();
        long processed = 0;

        while (processed < total) {
            List<ContentBase> batch = 
                contentBaseMapper.selectPage(processed, batchSize);
            
            List<ContentBaseEsDoc> docs = batch.stream()
                .map(ContentBaseEsDoc::fromEntity)
                .collect(Collectors.toList());

            contentIndexService.upsertDocuments(docs);
            processed += batch.size();
            
            log.info("ES 全量同步进度: {}/{}", processed, total);
        }
        log.info("ES 全量初始化完成，总数: {}", total);
    }

    /**
     * 增量同步：根据 contentId 更新 ES 文档
     */
    public void incrementalSync(String contentId) {
        ContentBase contentBase = contentBaseMapper.selectByContentId(contentId);
        if (contentBase == null) {
            log.warn("content_base 中不存在 contentId={}，跳过 ES 同步", contentId);
            return;
        }

        ContentBaseEsDoc doc = ContentBaseEsDoc.fromEntity(contentBase);
        contentIndexService.upsertDocuments(List.of(doc));
        log.info("ES 增量同步完成: contentId={}", contentId);
    }

    /**
     * 批量增量同步
     */
    public void batchIncrementalSync(List<String> contentIds) {
        if (CollectionUtils.isEmpty(contentIds)) {
            return;
        }
        List<ContentBase> list = contentBaseMapper.selectByContentIds(contentIds);
        List<ContentBaseEsDoc> docs = list.stream()
            .map(ContentBaseEsDoc::fromEntity)
            .collect(Collectors.toList());
        contentIndexService.upsertDocuments(docs);
    }
}
```

## 三、与 RawContentSyncService 的集成方案

### 3.1 方案一：调用方触发（推荐）

`RawContentSyncService.sync()` 执行完成后，由调用方主动触发 ES 同步。

```java
// RawContentSyncTask 中
public void process(RawContentInfo raw) {
    // 1. 同步到 MySQL 宽表
    rawContentSyncService.sync(raw);
    
    // 2. 同步到 ES
    contentIndexSyncService.incrementalSync(raw.getContentId());
}
```

**优点：** 简单直接，调用方可控
**缺点：** 同步失败会导致 ES 与 MySQL 不一致

### 3.2 方案二：数据库变更监听（CDC）

使用 Canal 或类似工具监听 MySQL binlog，自动触发 ES 更新。

**优点：** 解耦业务代码，最终一致性
**缺点：** 引入中间件，增加运维复杂度

**建议**：当前阶段使用方案一，待数据量进一步增长后评估方案二。

## 六、定时更新 AI 标签

由于 AI 打标是异步执行且偏随机，ES 中的 `aiTag` 字段需要通过定时任务更新。

### 6.1 定时任务逻辑

```java
@Service
public class AiTagEsSyncTask {

    @Resource
    private ContentLabelMapper contentLabelMapper;
    
    @Resource
    private ContentIndexService contentIndexService;

    private static final int BATCH_SIZE = 500;

    /**
     * 定时同步 AI 标签到 ES
     * QSchedule: 每天凌晨执行
     */
    public void syncAiTags() {
        // 查询近期有 AI 标签更新的 content
        List<ContentLabel> updatedLabels = 
            contentLabelMapper.selectRecentUpdated(3);  // 近 3 天
        
        List<ContentBaseEsDoc> docs = updatedLabels.stream()
            .map(label -> {
                ContentBaseEsDoc doc = new ContentBaseEsDoc();
                doc.setContentId(label.getContentId());
                doc.setAiTag(parseAiTag(label.getAiTag()));
                return doc;
            })
            .collect(Collectors.toList());

        // 分批写入 ES
        List<List<ContentBaseEsDoc>> batches = 
            Lists.partition(docs, BATCH_SIZE);
        
        for (List<ContentBaseEsDoc> batch : batches) {
            contentIndexService.upsertDocuments(batch);
        }
        
        log.info("AI 标签 ES 同步完成，更新数: {}", docs.size());
    }
}
```

- **过期清理**：超过 30 天的索引自动删除

## 九、风险与注意事项

1. **数据一致性**：方案一采用最终一致性，如对一致性要求高，需引入重试机制
2. **ES 内存**：全量初始化期间注意 ES JVM 内存，避免 OOM
3. **mapping 变更**：上线后如需修改 mapping，需重建索引并重新导入
4. **网络延迟**：ES 与 MySQL 不在同一网络时，需评估同步延迟
